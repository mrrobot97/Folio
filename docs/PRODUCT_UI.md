## 数据与电源行为

首页不硬编码日期、电量、图书或阅读时长。未校时显示“日期未设置”，有统计历史的空书架仍可进入统计。图书扫描失败显示“书架暂时不可用”，不伪装为首次使用。首页的“书架”“继续阅读”“搜索”分别调用不同导航意图。

统计页面从阅读服务取得快照，绘制回调不查询硬件、不打开资源或写 NVS；字体引擎按其缓存策略读取字形数据。退出阅读、菜单和睡眠是否正确暂停计时，由阅读服务及主循环生命周期负责。统计保存状态与阅读进度分开呈现，不能通过一个保存成功隐藏另一个失败。长期未归属日期的时长不追溯填入任何一天。

设置中的字号是新书默认值；已打开图书的未应用排版草稿由阅读模块管理。设置保存失败保持原设置并显示提示。FAST/ECO 的保存、断电条件和恢复不能由页面直接跳过：页面只设置 `request_sleep` / `request_poweroff`。休眠和关机并非等价；关机有独立确认，电源管理由统一处理器执行。

进度 v3 等长保存字号来源，继续读取 v1/v2；超出排版配额的临时默认阅读可取消、退出并在重开时按当前默认解释，不误用旧 native 单位。真实编辑保存失败时保持 RAM，只有明确放弃才丢弃该编辑。旧固件不识别 v3，降级数据兼容尚未验证。

内置存储页面进入、绘制和重试挂载均不会调用格式化。只有经过清除风险说明及最终确认才调用 `book_store_initialize_flash(true)`，调用前再次检查是否已挂载；已挂载时取消初始化。成功后由阅读服务恢复钩子清除旧运行态并重新建立存储状态。初始化失败不宣称恢复成功。此流程需要真机首次初始化、已有有效分区、损坏分区及断电故障验证。

## 字体与刷新

共享 `folio_ui.c` 延续官方 `ttf_font` 字形缓存和 EPD 图形接口。设计稿字号为 CJK em，而官方接口以 ascent-descent 高度缩放；产品 UI 与正文/候选预览共同使用字体真实 unitsPerEm 和垂直度量换算，避免照抄设计数字后实际文字缩小。UTF-8 长标题按实际字宽省略，不拆开码点。固件内置子集仍需要包含全部新文案；替换用户字体、度量差异和实际字重需要设备验收。

同一排版字段内调整字号、字重、行距、边距、缩进或背景时，保持标题和底栏不变，预览与控件包围区 `[32,194,620,884]` 只提交一次 GL16；逻辑区域 **548,080 像素（全屏65.90%）**。测试验证实际像素变化都在该区域内，重复选择当前值不刷新；这不是物理扫描或耗电结论。

日历选日绘制旧日期、新日期和明细，再合并包围矩形进行一次 GL16 提交，避免三次提交触发三次波形扫描和三次软刷计数。测试的 10 月 9 日→8 日场景，提交区域为 **389,360 像素（全屏 46.81%）**，实际范围随日期位置变化。月份切换同样合并月标题、日历和明细后提交一次。原波形、GL16 与驱动周期清理/错误恢复保留；不承诺零黑闪、无残影或固定耗时。包围区域面积不等于硬件物理扫描面积，主机测试只证明提交次数和变化像素覆盖。

## 验证与后续覆盖

运行 `./tests/ui/run.sh` 可复跑生产页面回调的主机绘制、日期边界、导航、保存失败及初始化确认测试，并生成 PNG。详情见 `tests/ui/README.md`。主机测试使用明确的状态 fixture，不能当作硬件电量、真实阅读记录、面板效果或功耗证据。

尚未实现/尚未完成设计级替换的范围包含全局书签、原书封面提取、按可靠导入时间排序、完整产品化 TF/传书/诊断子页，以及其余未在本表列出的画板。自动休眠策略待完整接线。OTA、壁纸导入、阅读草稿与字体发布分别由对应模块负责，不能因本页面存在入口便认定该模块通过真机验收。


## 排版草稿与字体子流程

从书中打开“字体与排版”编辑本书的 `BOOK` 会话；从设置的“默认字体与排版”“默认阅读背景”或字体管理入口编辑 `DEFAULTS` 会话。默认设置只影响随后新打开的图书，不会打开或覆盖当前书。

根页显示根草稿。字号/字重、行距/边距/缩进、字体、背景各自拥有进入字段页时的快照与临时候选；“取消”只取消当前字段，之前已保留到根草稿的其它字段仍在。“保留到草稿”只合并当前字段，不改变活动排版。“应用更改”/“保存默认”才请求完整持久事务；失败显示错误并保留原活动值和全部草稿。

根页取消或 KEY3 离开会显示放弃确认。继续编辑恢复原字段和候选；放弃成功后回到模型捕获的阅读/设置来源。KEY3 还会在该来源打开菜单，关闭菜单后不会回到已关闭的编辑器。放弃的持久屏障失败时保留草稿，重试按钮继续执行放弃，绝不能转成应用。

字号端点 36/72 会显示禁用按钮，也不会调用模型进行越界修改；每步正好4。常规/适中/加粗对应400/500/700，并读取候选字体实际轴能力；静态或不支持的字重不可点击，不通过重复描边伪造加粗。更换字体不会悄悄重置其它字段，不受支持的组合由提交前验证拒绝并保留草稿。

界面固定使用 UI 字体角色；正文和候选预览拥有独立角色。字体文件只在事件阶段准备，渲染阶段只选择已准备角色并绘制。预览缺字检查针对实际样例，不等于完整正文覆盖证明。内置界面子集需要单独确认，缺失的TF字体不会自动换成它。字号页/字体页显示样例，行距页额外按真实行距、边距和首行缩进画段落；大字号导致样例容量变小时不会越过卡片边界。

上传字体是同一排版会话的临时子流程。进入前模型必须保存字段候选、会话身份和返回栈；关联保存失败时不会启动传输。传输停止后回到原字体选择器；返回时重新扫描/核对资源。FAST 唤醒或冷恢复的网络停启与资源验证由统一生命周期负责，UI进入回调不会自行启动HTTP。恢复层可利用所记录的字段/选择/滚动状态继续安全编辑；这不等于自动应用草稿。

运行 `./tests/ui/run_format.sh` 生成真实生产字体引擎与页面回调的截图；`python3 tests/ui/compare_format_design.py` 生成23组以上的684×1216原尺寸对照。原官方字体页仅作为工程诊断保留，产品入口使用新书默认草稿流程。每批输出 `render-manifest.json`，包含字体大小/SHA256、生产源码SHA256和生成时间，用于识别是否重嵌入了新字体。此套件在服务边界注入ACK失败和资源目录，验证界面语义；真实记录事务、恢复/旧盘屏障与预备分页由独立阅读模块测试验证，不能由UI截图代替。
