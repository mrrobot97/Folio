# 阅读状态主机测试

在仓库根目录运行 `sh scripts/test_reader.sh`。脚本用本机 C 编译器、AddressSanitizer 和 UndefinedBehaviorSanitizer 编译真实的统计、检查点和字号会话代码；临时文件只写 `/tmp/folio-reader-*`。

覆盖内容：单调时间、5 分钟可配置闲置截断、暂停与恢复、未知日期、可信时钟切换不重分配旧数据、跨午夜和闰日、逐书逐日查询、统计容量上限及未分类累计、CRC 损坏与截断、保留前一有效槽、写失败保留 RAM、未知 schema 拒绝覆盖、未落盘增量断电丢失、草稿不等于应用、失败的应用/取消不能关闭旧草稿、逐书偏好隔离、原文件变化拒绝覆盖、会话包与休眠来源引用必须同时 ACK、引用代数失配拒绝恢复、关闭/无关联来源的持久屏障、未支持 DEFAULTS/字体子流程拒绝恢复、排版记录配额。

当前已实现的持久排版会话只包含 `BOOK` 字号。schema 同时记录字段支持掩码、已应用值和基线版本、根草稿、字段入场值、待合并字段掩码、会话/修改/休眠 ID、工具条或正文来源、当前面板/选择、页内返回栈、字体路径/大小与书籍路径/大小/mtime。其他字段、DEFAULTS 与 FORMAT_DRAFT 字体子流程没有开放；保存与恢复会拒绝伪造的支持标记。普通字体页仍是独立的全局选择入口，须先应用或取消字号草稿。

实际固件接线位于 `main/apps/app_book.c`；这些宿主测试不能代替该文件的 ESP-IDF 构建、页面交互、FAT 断电注入或 PMU 唤醒真机验证。CRC 双槽、flush/fsync 与回读验证也不是对实际 FAT/Flash 任意断电行为的保证。文件系统元数据断电恢复、媒体热拔插和耗电必须在设备上验证。

普通重挂载使用独立恢复钩子：首次未能载入历史时，重新载入的磁盘历史与 RAM 新增量有界合并；合并后的写入失败仍保留 RAM，后续重试不重复累加。未知版本/损坏记录阻止写入，两侧原数据保留。此流程不同于用户明确确认初始化后丢弃旧 RAM 并重新读取磁盘的流程。换书前若旧会话未关闭，真实持久化失败就拒绝替换唯一 RAM 草稿，拔卡后也保持该限制。

`folio_reading_summary_at(now_ms)` 在非阅读页面和 FAST 唤醒后按当前单调时间计算可信日期，仅查询，不补记暂停或睡眠时间。首页/统计留屏时只在日期改变后重绘；统计的历史选日保持原位置。

统计在 PSRAM 中使用有界状态，最多 64 本路径、4096 个书籍×日期桶；容量溢出保留总时长并明确累计为未分类。两份满容量统计检查点合计最多 169,096 字节。字号会话最多 128 本，每本两份 668 字节文件，来源引用两份 340 字节；不自动删除旧记录换空间。总文件内容上限约 333 KiB，不含 FAT/WL/目录分配开销，且不代表共享 FAT 已为其预留可用空间。存储不足会保留失败状态。

运行输出中的查询耗时是本机 sanitizer 构建的 CPU 时间，不是 ESP32-S3 响应、刷新或功耗指标。固件每 120 秒在有脏统计时尝试一次检查点，离页和睡前也请求保存；未保存时间仍可能在突然断电时丢失。
